# 05 東京23区の全道路 (ネイティブ)

## 依頼

> ノート PC のデスクトップアプリとして、東京23区の道路を1本も間引かずに表示して、144Hz のモニタでカクつかずにパン・ズームしたい。ブラウザは使いたくない。起動は一瞬で。

## 読み取った要件

| 要件 | 数値にしたもの |
| --- | --- |
| 1 本も間引かない | highway=* の way 286,195 本、120 万区間を全部、全ズームで描く |
| 144 Hz でカクつかない | 23 区全体から渋谷まで 128 倍ズームして戻る 600 フレームで、GPU の処理が終わるまでを含めた frame_ms p95 6.9 ms 以下。全体表示も別に p95 6.9 ms 以下 |
| 起動は一瞬 | プロセス起動から最初のフレーム完了まで、初回起動 (シェーダ未キャッシュ) を含む最大値が 300 ms 以下 |
| ブラウザを使わない | C11 と EGL と OpenGL ES 3.0 だけ。実行ファイル 40 KB 以下 |
| ノート PC で軽い | 2 回目以降の起動の常駐メモリ p50 150 MB 以下 |
| 正しく描けている | データ中の高速道路の頂点を画面中央に置き、そのピクセルが高速道路の赤であることを確かめる |

## やらないこと

ラベル、アイコン、建物、面、タイル、LOD、間引き、回転、3D、ブラウザ、ウィンドウツールキット (X11 を直接使う)。

## 設計

- 道路は区間のインスタンス描画。1 区間 = 4 頂点のストリップで、頂点シェーダが区間の向きに直交して道路幅だけ広げる。端を幅の半分だけ延ばすので (四角い端点)、つなぎ目が欠けない。全道路網を 1 回のドローコールで描く。
- 区間リストを別に持たない。頂点配列そのものを、1 頂点ずらして 2 つのインスタンス属性 (始点と終点) として読む。道路の終わりの頂点だけ種別を 255 にして、その区間は描かない。1 頂点 5 バイト。
- 描画順はベイク時に決める (細い道から先、太い道が上)。実行時にソートしない。
- データは mmap してアップロードしたら munmap する。プロセスにデータのコピーを残さない。
- リンク済みのプログラムをデータの隣 (`roads.bin.prog`) に保存し、次回からは `glProgramBinary` で読む。NVIDIA の GLSL コンパイラを読み込まずに済むので、常駐メモリが約 58 MB 減り (2 回目以降の p50 124 MB、初回 166 MB)、最初のフレームが 183 ms から 107 ms になる。ドライバが受け付けなくなったバイナリはリンクに失敗するので、そのときはコンパイルし直す。
- ベンチモードは EGL device platform のピクセルバッファで描く (X も Wayland もいらない)。ウィンドウモードは Xlib で窓を 1 枚開くだけ。

## 計測で分かったこと

- フレーム時間は表示範囲によらず約 1.05 ms で一定。120 万インスタンス (480 万頂点) の頂点処理が支配的で、ラスタ化の時間はほとんど影響していない。
- 常駐メモリの内訳: 起動時 2.7 MB、EGL と GL の初期化で 93 MB (ドライバ)、データのアップロードで +7 MB、シェーダのコンパイルで +59 MB、最初の描画で +18 MB。描画器自身が使っているのはアップロード分くらいで、残りはドライバが使う分。
