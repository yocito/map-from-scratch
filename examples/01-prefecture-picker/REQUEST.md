# 01 都道府県ピッカー

## 依頼

> 自治体の観光サイトの記事に、都道府県を選ぶ日本地図を埋め込みたい。クリックやタップで選んだ都道府県で記事を絞り込む。外部ライブラリは入れられないし、ページが重くなるのは困る。

## 読み取った要件

| 要件 | 数値にしたもの (spec.json の budgets) |
| --- | --- |
| ページが重くならない | 配布コード gzip 1,500 B 以下、データ 16 KB 以下 |
| スマホでも使える | 390×844、DPR 3、CPU 4 倍スロットルで計測 |
| すぐ出る | 初回描画 p50 300 ms 以下 |
| ホバーとタップに即応 | 再描画の記録 p95 2 ms 以下、ホバー中のフレーム間隔 p95 20 ms 以下、当たり判定 p95 1 ms 以下 |
| 選んだ県を記事側へ渡す | クリックで `prefecture` イベント ({code, name})。東京の内側をクリックして JP-13 が届くことを毎回確かめる |

## やらないこと

パン、ズーム、回転、3D、タイル、地図上の文字、実行時の投影、WebGL、データ形式のパーサ。地図の範囲は固定で、文字はページの DOM が出す。

## 設計

- 47 都道府県を、ベイク時に 1,000 単位グリッドの SVG パス文字列にする (相対整数座標、Douglas–Peucker 1.2 単位、小さな離島は落とす)。ブラウザ内蔵の `Path2D` がそのままパースするので、JS にパーサがない。
- 当たり判定は `isPointInPath`。47 本を順に試しても p95 0.01 ms で、空間索引はいらない。
- ホバーと選択では 47 県を全部描き直す。4 倍スロットル下でもフレーム間隔は p95 1.5 ms。変わった 1〜2 県だけを塗り直す版 (p95 1.3 ms) も作ったが、予算に対して差がないので、コードの小さい全面描き直しを採った。
- コンテキストを失って戻ってきたら (`contextrestored`) 全体を描き直す。戻ったキャンバスは白紙で変換行列も初期化されていて、当たり判定はその変換行列に頼っているため。

## 計測で分かったこと

- 最初の計測方法 (描画ごとに `getImageData` で同期) は、描画ではなく GPU からの読み戻しを測っていた (p50 14 ms のうち描画の記録は 0.02 ms)。今は rAF のフレーム間隔で測る。
- 一時期、GPU バックの 2D canvas が生成から約 300 ms でコンテキストを失い、当たり判定が全部外れた。東京クリックの機能確認で発覚した。CPU バック (`willReadFrequently: true`) に切り替えて回避したが、原因は後で、ハーネスが Chromium に渡していた `VulkanFromANGLE` フラグによる GPU プロセスのクラッシュだと分かった。フラグを外した条件で比べ直すと、GPU バックはホバー中のフレーム間隔 p50 0.7 ms (CPU バックは 14.8 ms)、初回描画 92 ms (同 134 ms) で、明らかに速い。それで GPU バックに戻した。
