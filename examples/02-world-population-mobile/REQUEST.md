# 02 スマホで世界の人口

## 依頼

> スマホで、世界の国を人口で塗り分けた地図をピンチで拡大して、タップした国の名前と人口を出したい。

## 読み取った要件

| 要件 | 数値にしたもの |
| --- | --- |
| スマホで開ける重さ | データ gzip 600 KB 以下 (4G で約 1 秒)、コード gzip 4 KB 以下 |
| スマホで動く | 390×844、DPR 3、CPU 4 倍スロットル |
| ピンチが滑らか | 世界全体から日本まで 32 倍ズームして戻る 300 フレームで、GPU 完了までの frame_ms p95 16.7 ms 以下 |
| タップに即応 | タップ 1 回の当たり判定 p95 8 ms 以下。東京・パリ・ブラジリア・太平洋で正しい国 (海は国なし) が返ることを毎回確かめる |
| すぐ出る | 初回描画 p50 1.5 s 以下 |

## やらないこと

3D、地球儀、回転、タイル、地図上の文字 (名前と人口は DOM のパネル)、実行時の投影計算、連続アニメーション。

## 設計

- 塗り分け図なので、正積図法の Equal Earth でベイクする。画面上の面積がそのまま地上の面積になる。投影はベイク時に済ませるので、シェーダはカメラの平行移動と拡大だけ。
- 頂点は 16 ビット整数 (世界の外接矩形を 65,536 分割、1 段は約 0.3 km) と国 ID。塗りつぶし (earcut) と国境線で同じ頂点を共有する。
- 国境線のインデックスは配らない。各リングの頂点数だけを配り、読み込み時に隣り合う頂点を結ぶ。座標と三角形インデックスは前の値との差分 (2^16 と 2^32 で折り返す) で保存し、gzip が効く形にする。この 2 つで data gzip が 1.32 MB から 474 KB になった。
- 色は国ごと 1 テクセルのパレットテクスチャ。選択は uniform 1 つで切り替える。
- 当たり判定は ID 描画。カメラの中心をタップ位置にして 1×1 の FBO に描くので、ラスタライズされるのは 1 ピクセルだけ。読み戻しも 1 ピクセル。
- 描くのはカメラが動いたときだけ (rAF を 1 回予約)。止まっているときの GPU 負荷はゼロ。

## 計測で分かったこと

- headless Chromium は起動直後に GPU プロセスを 1 回作り直す。その前に作った WebGL コンテキストは失われ、当たり判定が全部 0 を返した。ハーネスは今、WebGL コンテキストが 1 秒生き残るまでウォームアップしてから計測する。
- 頂点ストリームを分けた (インターリーブをやめた) 版では gpu_ms が 0.10 ms から 0.22 ms に増えた。予算には十分収まるので、このままにしている。
